# P13-0 Current Gap Matrix — the source-backed audit

**Status:** P13-0 deliverable 1 of 2 (the companion decision record is
[ADR-0007](../../docs/architecture-governance/adr/ADR-0007-p13-agent-led-connector-and-payment-architecture.md)).
**Surveyed commit:** `ab5b789` (`main`, 2026-10-22 — post PR #4 + PR #5).
**Method:** direct code reads of the working tree at the surveyed commit. Every
row cites files that exist at that commit (or states that none exists). Nothing
in this matrix is derived from the P13 UX reference SVGs, PR prose or chat —
those are design targets, not implementation state.

Legend — `Plane`:
- `CONTRACT` — typed, tested, versioned code exists as a pure contract/fold
  (no runtime wiring).
- `SUBSTRATE` — working machinery exists in the ZCode-derived platform
  (host/services/desktop), currently serving substrate capabilities only.
- `ABSENT` — no implementation exists anywhere in the repository.
- `WIRED-APP` — reachable on a real product route doing real work today.

## 4. Headline determination (what P13 actually builds on)

1. **The contracts floor is unusually complete.** Connection forms, lifecycle,
   scopes, credential isolation, transport, idempotency, result envelopes,
   sandbox/live, progress states, ambiguous outcomes, mission vocabulary and
   the workspace store port ALL exist as tested contracts. P13 is a WIRING
   wave, not a vocabulary wave: the three lanes implement RUNTIMES behind
   contracts that already exist.
2. **The substrate provides every host mechanism P13-B needs**: encrypted
   credential storage at rest (`ICredentialService`), a proven system-browser
   OAuth + deep-link-return pattern (`oauthService` + `desktopOAuthDeepLink`),
   OS protocol registration, and a host service seam
   (`IPaySwapDesktopService`) with a persistent store. No new host mechanism
   class is required.
3. **The genuinely-absent planes** (P13's real scope): the shared composer +
   typed intent router (A), the payment-PSP registry + connection session
   authority + Stripe adapter + durable broker binding (B), and the payment
   task runtime + authorization gate + reconciliation wiring (C).
4. **Voice is ABSENT everywhere** and must be declared honestly, never
   simulated (P13-A law).
5. **The embedded/isolated onboarding browser is NOT in P13** — the
   system-browser path with validated deep-link return is the architecture
   (ADR D2), matching the UX reference's "otherwise the system browser is used
   with validated return/resume handling."
6. **No Stripe account credentials exist in this station.** The Stripe
   test-mode vertical slice is implementable and verifiable ONLY against
   operator-provided test-mode credentials; without them P13-B lands the full
   machinery with the honest "credentials not provided" terminal state and the
   work order's "if required live setup absent, blockers are exact and status
   remains unverified" clause governs (ADR D1/D8).
